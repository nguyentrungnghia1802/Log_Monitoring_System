# Log Monitoring Spring Boot Starter

This starter exposes the bounded Java SDK through Spring Boot configuration
and dependency injection. It is disabled by default, so local tests do not
start a worker or make network calls unless `log-monitoring.client.enabled`
is explicitly set to `true`.

## Dependency

In a Spring Boot 3.3 / Java 21 application:

```groovy
implementation project(':sdk:log-monitoring-spring-boot-starter')
```

For a published artifact, use the versioned Maven coordinate generated by the
release process instead of the project dependency.

## Configuration

Keep the API key outside source control. The following YAML shows every SDK
bound that the starter maps to `LogMonitoringClientConfig`:

```yaml
log-monitoring:
  client:
    enabled: ${LOG_MONITORING_ENABLED:false}
    endpoint: ${LOG_MONITORING_ENDPOINT:https://logs.example.com}
    api-key: ${LOG_MONITORING_API_KEY:}
    service: ${spring.application.name:spring-boot-service}
    environment: ${APP_ENV:local}
    queue-capacity: 5000
    batch-size: 100
    max-wait-ms: 500
    max-retries: 3
    backoff-ms: 500
    max-backoff-ms: 30000
    jitter-ms: 100
    max-retry-after-ms: 30000
    request-timeout-ms: 2000
    flush-timeout-ms: 5000
    max-message-length: 4000
    max-exception-message-length: 1000
    max-stack-trace-length: 4000
    max-context-entries: 32
    max-tag-entries: 32
    max-context-key-length: 64
    max-context-value-length: 512
```

Inject `com.example.logmonitor.sdk.LogMonitoringOperations` in application
services. Disabled mode supplies a no-op implementation that returns `false`
for local queue admission, reports `DROPPED_BY_POLICY` for explicit submits,
and always returns from `flush()` without network activity. Enabled mode
supplies the real `LogMonitoringClient`, which closes with the Spring context
and keeps the SDK's bounded shutdown window.

The Actuator health indicator reports enabled/no-op state and bounded queue
depth without exposing endpoint or credential values. When a `MeterRegistry`
is available, the starter publishes low-cardinality submission outcome
counters and queue depth/capacity/running gauges. A server `202` remains only
server admission to the platform's bounded in-memory queue; it is not a claim
of durable persistence.

Validate the starter with:

```bash
./gradlew :sdk:log-monitoring-spring-boot-starter:test --no-parallel
```
